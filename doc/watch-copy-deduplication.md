# 自动监听跳过已压缩图片的副本

2026-11-04。本次源码实现针对 iOS 成品复制到 Android 目录后再次压缩的问题。自动监听按文件字节匹配已完成的图片记录；手动压缩不受此匹配限制。

## 行为与实现

- 复制、改名或跨目录放置的文件，只要与已登记成品的完整内容一致，就跳过自动压缩并登记新位置。已登记副本后续不变时仅检查文件元数据。
- 内容修改后重新判定，哪怕文件大小不变；图片写入尚未稳定或校验期间发生替换时延后处理。
- `OutputRecords.status()` 保留文件对象识别；新增 `watchStatus()` 用于监听事件、监听队列过滤和自动任务执行前检查。手动请求不带 `watch_version`，仍可进入真实压缩流程。
- `content-v1/<文件大小>/<SHA-256>` 为持久化索引。先筛文件大小，再分块读取候选内容。内存最多缓存 128 个大小分组，分组目录的元数据变化时刷新，以接收其他处理进程新增的记录。
- 监听服务内的候选副本读取和登记最多同时执行 2 个，多个监听目录共享该限制；独立压缩 worker 的执行前核验使用各自的限制。不同大小的新输入不读取图片内容，视频不走此索引。
- 首次使用扫描旧记录文件补建索引，不扫描历史图片内容；完成后持久化标记，重启直接复用。坏的无关旧记录不阻断健康文件，自身路径的坏记录仍按原机制报告错误。
- 启动监听仍只对已有目录建立元数据基线，不新增全目录内容校验。空闲时无新增图片轮询；原有根目录存在性检查保持不变。
- 新版本的撤销恢复标记 `copyEligible: false`：恢复原稿在原位置保持监听保护，但不会仅因撤销而让原稿的副本也被认作压缩成品。

只有完成处理的记录提供指纹，普通导入、未处理或失败任务不建立副本索引。原有“未达到压缩收益阈值而保留原文件”的成功处理仍属于已完成处理。历史记录未保存压缩与撤销来源，迁移沿用原先“已处理”语义，不能反推旧记录的来源。

- 更新既有旧记录与文件身份测试的副本预期后，针对这两组再执行回归，24/24 通过，结果见 `watch-copy-testing/20261104/legacy-final.log`。

从仓库根执行：

```sh
./packages/picsharp-sidecar/node_modules/.bin/tsx --test --test-concurrency=1 \
  apps/picsharp-app/tests/*.test.* packages/picsharp-sidecar/tests/*.test.ts
```

## 批量复制性能

环境：本机 macOS / Apple Silicon，Node v22.22.1，本地临时目录；每组单次测量。使用真实 `fs.watch` 和默认约 500 ms 图片写入稳定等待。以最多 16 个复制请求并发制造批量输入；候选副本内容读取上限为 2。

“全部识别耗时”从开始复制计时，包含复制、写入稳定等待、内容检查和登记，不能等同于纯指纹计算耗时。测试统计入队行为，不实际运行压缩器；旧逻辑对照仅用于比较筛选开销，不包含它后续会触发的压缩耗时。

| 场景 | 数量 | 总大小 | 复制完成 | 全部识别 | 进入压缩队列 | 内容读取峰值并发 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 用户词典 iOS 图片 | 4 | 0.47 MiB | 0.71 ms | 520.09 ms | 0 | 2 |
| 词典图片重复复制 | 1,000 | 117.34 MiB | 221.33 ms | 1,068.43 ms | 0 | 2 |
| 256×256 随机 PNG，旧识别逻辑 | 1,000 | 188.16 MiB | 180.78 ms | 907.71 ms | 1,000 | 0 |
| 256×256 随机 PNG，新副本识别 | 1,000 | 188.16 MiB | 190.83 ms | 1,157.57 ms | 0 | 2 |
| 1024×1024 随机 PNG | 100 | 300.64 MiB | 168.63 ms | 857.63 ms | 0 | 2 |

在这次 1,000 张随机 PNG 的对照中，筛选阶段总耗时增加约 250 ms，同时避免了 1,000 次压缩入队。每张候选副本读取一次；各组额外 1 秒空闲观察中，图片读取次数均为 0。

同进程连续运行的各组观测到峰值 RSS 112–171 MiB；词典 1,000 张组相对该组开始增加约 27.67 MiB。这个值含 Node、图片库及前序场景的内存保留，不是可独立归因于功能的精确内存成本。事件循环最大采样间隔为 12–18 ms，不能据此替代桌面界面流畅性验收。

另用 2,000 条历史记录测试一次性迁移：补索引并识别第一张副本 73.11 ms；创建新记录实例后识别下一张副本 1.34 ms。该样本模拟重复使用同一成品的历史，不代表 2,000 张不同内容的最坏情形。

可复跑脚本：

```sh
./packages/picsharp-sidecar/node_modules/.bin/tsx \
  packages/picsharp-sidecar/benchmarks/image-copy-watch.ts
# 可选首参数：只读 PNG 样本目录；脚本复制到临时目录测试，不修改原图。
./packages/picsharp-sidecar/node_modules/.bin/tsx \
  packages/picsharp-sidecar/benchmarks/image-copy-watch.ts --legacy-only
```

## 验收边界

已验证本机文件系统事件与实际手动图片处理函数；未替换 `/Applications/PicSharp.app`，未进行新安装包的桌面点击验收。未测试机械硬盘、网络共享、外置盘或 Windows/Linux 性能。指纹按完整文件字节比较；视觉相同但编码或文件内元数据不同的图片不会被视作同一副本。自动跳过不随当前质量、尺寸或水印设置变化，需要应用新设置时使用手动压缩。
